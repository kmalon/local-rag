Spring Boot 3.5 + Spring AI 1.1 app (Ports & Adapters, feature-packaged). Ingests local files/docs via REST API, creates embeddings (Spring AI + OpenAI), stores to PostgreSQL pgvector. Package: pl.km. Build: Gradle.

Packages: `rag` (RAG feature: adapter/application/config, public `RagFacade`), `mcp` (MCP server feature: `RagMcpTools` @Tool + `McpServerConfig`), `shared` (shared kernel: `QueryResult`, exceptions), `config` (SecurityConfig) + `web` (GlobalExceptionHandler) = common at root. Cross-feature access only via `RagFacade` returning shared-kernel types.

Auth: OAuth2 Resource Server (JWT) via Keycloak realm `local-rag`, roles `rag_admin` (ingest) / `rag_user` (query) / `rag_mcp_user` (MCP). Two filter chains, both validating `iss` + `aud`, with different audiences: REST → `rag-platform` (broad, shared across platform APIs, from optional scope `rag-api`); `/mcp` → `rag-mcp` (MCP-only, from optional scope `rag-mcp-api`) plus 401 w/ RFC 9728 `resource_metadata` hint. Two clients, one scope each, so the audiences are mutually unreachable: `rag-api-client` (REST users, holds `rag-api` only) and `rag-mcp-client` (AI agents → MCP, holds `rag-mcp-api` only). A client cannot request an optional scope it isn't assigned, so an agent can't mint a REST token and vice versa. `rag-api-client` is confidential (secret via `secrets/rag_api_client_secret.txt`, substituted into the realm import) — `client_id` is an identifier, not a credential, so the secret is what stops a local process from running its own flow against REST; `rag-mcp-client` stays public since an agent can't keep a secret. Callers request `scope=openid rag-api` or `scope=openid rag-mcp-api`. Realm import declares the built-in `roles` client scope itself (declaring any `clientScopes` stops Keycloak seeding the built-ins, and without `roles` there is no `realm_access.roles` ⇒ everything 403); every scope a client references must therefore be declared in the realm file. RFC 9728 `resource` stays the URI `http://localhost:8080/mcp` (`mcp.resource`), separate from the `aud` value. Metadata at `/.well-known/oauth-protected-resource[/mcp]` (public).

Query: pgvector over-fetches a candidate pool, local cross-encoder reranker (ms-marco-MiniLM ONNX via onnxruntime) re-scores; score threshold applied to reranker output. Pool derived from the request, not fixed: `poolSizeFor(topK) = min(max-candidates, max(min-candidates, topK × over-fetch-factor))` (4 / 20 / 80), so the over-fetch ratio is guaranteed rather than an accident of the requested `topK` — a fixed pool gave 1× at the top of the range, where the reranker could only reorder what vector search already picked.

Input rules: value objects in `rag/application/model` (`Question`, `TopK`, `MinScore`, `DocumentName`, `DocumentContent`), built inside the port implementations, so REST and MCP get identical rules while ports/`RagFacade` keep primitive params. Non-blank text; `minScore` ∈ [0,1] (fixed — reranker scores are sigmoid); `topK` ≥ 1 (constructor invariant) and ≤ `QueryProperties.maxTopK()` = `max-candidates / over-fetch-factor` = 20 (factory `TopK.boundedBy`, the most servable at the promised ratio), default 5. Violations → `InvalidInputException` → REST 400 / MCP `RagSearchArgumentException` (distinct from `RagSearchUnavailableException`: fix the argument, don't retry — and it must be caught before the facade's catch-all, which would otherwise tell an agent to retry forever).

MCP: Spring AI MCP server (`spring-ai-starter-mcp-server-webmvc`), **stateless Streamable HTTP** (`spring.ai.mcp.server.protocol=STATELESS`) at single endpoint `/mcp` — one POST per JSON-RPC message, JSON response, no session id/SSE stream, so no server→client features (sampling, roots, list-changed notifications). Read-only tool `search_rag_documents(question, topK, minScore)` delegating to `RagFacade`; arguments passed through untouched — the rules live in the application layer (see Input rules). `McpServerConfig` assembles the tool definition (`ToolDefinitions.from(method)` + patched schema) instead of using `MethodToolCallbackProvider`, so the deployment's `topK` range reaches the agent as JSON Schema `minimum`/`maximum` + prose; annotations cannot hold a config value. The range crosses the module boundary via `RagFacade.limits()` → `RagSearchLimits`.

Infra: docker-compose (pgvector/pgvector:pg16 + Keycloak + app image). Tests split: unit in `src/test` (`test` task); integration (`@WebMvcTest`+) in `src/integration-test` (`integrationTest` task, wired into `check`).

k8s/minikube (alongside compose, not replacing it): `k8s/` kustomize manifests + `k8s/deploy.sh` (preflights secrets & reranker files, builds image into minikube's docker daemon, applies). `rag-db` StatefulSet+PVC (ClusterIP), `keycloak` Deployment (realm ConfigMap, same import script as compose), `rag-app` Deployment `replicas: 2` + HPA 2→5 @70% CPU (metrics-server addon). App/Keycloak Services are `LoadBalancer`, published by `minikube tunnel` on the **same** `localhost:8080` / `:8081` as compose — so issuer, `mcp.resource`, realm `redirectUris` and CORS are unchanged. Secrets built by `deploy.sh` from the same `secrets/*.txt`; app datasource still via `configtree:/run/secrets/`. Reranker/embedding ONNX ride in the image (`classpath:` default, `.dockerignore` keeps `models/` in) so a replica is self-contained. Only app-side change k8s forced: `spring-boot-starter-actuator` + `management.endpoint.health.probes` and `permitAll` on `/actuator/health/**` (kubelet carries no token; `show-details: never`).
